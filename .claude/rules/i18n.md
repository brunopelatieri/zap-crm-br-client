# i18n — dicionários e locale

- Toda string visível ao usuário é traduzida: chave nova entra nos **dois** dicionários na mesma alteração (`en.json` é a fonte, `pt-BR.json` espelha a árvore); rode `npm run i18n:check`.
- Preserve placeholders e sintaxe ICU (`{count}`, `{name}`): o check compara só a árvore de chaves, não os placeholders, e o `typecheck` não pega chave ausente.
- Sem prefixo de locale na URL (nunca `[locale]` nem `/pt-br/…`); o locale vem de `NEXT_LOCALE` → `NEXT_PUBLIC_APP_LOCALE` → padrão, e o middleware não o resolve.
- Mensagens de `/api/**` ficam em inglês; a UI mapeia o erro para uma chave.
- Validação de dado não segue o locale do usuário (use `deployment-locale.ts`).
- Datas passam `getDateFnsLocale(locale)`; idioma novo só em `SUPPORTED_LOCALES` (`src/lib/i18n/locales.ts`).
- `t` dentro de `.map()` sombreia `useTranslations`: renomeie a variável do map.

Detalhe: leia `docs/context/i18n.md`.
